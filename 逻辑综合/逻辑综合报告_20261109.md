# 北斗 B1I 六通道基带处理器逻辑综合报告

日期：2026 年 11 月 9 日。状态：阶段报告；16:16 用户确认虚拟机已关闭，完整六路尚未完成最终验收。

## 1. 实验目标与验收口径

将六个独立捕获、跟踪和电文解调通道映射到 TSMC28 标准单元，所有外部信号经过真实 PAD，完成同版网表的时序检查、最大/最小条件反标仿真和基于实际活动的平均功耗分析。六路共享连续输入 IF，采样率为 16.368 MHz；保持 64 路码相位相关、33024 点回放及两次 1 ms 非相干积分。

“综合完成”与“实验验收完成”分开判定。映射完成须有实际网表和 DDC、未映射及未解释黑盒数量为零；最终验收还须建立/保持和设计规则通过、有效路径约束完整、六路门级自检及反标通过、活动功耗来源可追溯。本报告不将单路结果乘六当作六路实测，也不将小探针后仿当作完整六路后仿。

## 2. 环境、工具及工艺条件

本次先执行 GitHub 拉取，工作基点为 `c744f25`。远端 Linux 虚拟机提供 4 个 CPU、9854 MiB 内存、无 swap；主机不支持本次增至 8 核。采用已验证的 SSH NAT 入口和严格主机指纹检查；作业以独立目录、源码 SHA256、后台进程和退出码归档，断线后可继续查询，不需要重启综合。

工具为 Design Compiler / PrimeTime K-2015.06、VCS 2014；RTL 回归使用本机 ModelSim 10.5。映射库为 `tcbn28hpcplusbwp40p140`，PAD 库为 `tphn28hpcpgv18`，信号 PAD 为 `PDDW04SDGZ_H_G`。

| 条件 | 标准单元 | PAD 核心/IO 电源 | 用途 |
| --- | --- | --- | --- |
| TT | 0.90 V、25 °C | 0.90 / 1.80 V | 单通道初次规模映射 |
| SS | 0.81 V、125 °C | 0.81 / 1.62 V | 完整候选最大条件及探针最大条件 |
| FF | 0.99 V、−40 °C | 0.99 / 1.98 V | 最小条件复核及探针最小条件 |

PAD 的 POC/VDDPST 接 IO 电源，VDD 接核心电源，VSS/VSSPST 接地。输入 PAD 的 OEN=1、REN=1，输出 PAD 的 OEN=0、REN=1。Bond Pad 属于物理阶段，本次未以无时序模型的物理单元替代信号 PAD。

## 3. 设计与约束

新增独立工程 `logic_synth/`，保留原接收机工程。六路通过同步配置口各自锁存 PRN、搜索步进与频点数，一路重捕获不清除其他路状态。低有效复位统一作用于六路，按下降沿附近释放建模。电文输出为去 NH 后的逐位 D1 数据；Costas 整体极性每次捕获只确定一次。

时钟周期约 61.094819 ns；保留 0.5 ns 时钟不确定度。核心预估与含 PAD 接口分别使用自己的 SDC，显式约束输入最大/最小延迟、输出最大/最小延迟、负载和转换。含 PAD 候选使用输出 1 pF 负载；预算属于本实验接口假设，不构成板级或布局布线签核。未通过降频、宽泛 false path、关闭 timing check 或放宽保持预算取得通过。

综合采用分层复用：先完成单通道映射，再导入同版 DDC、绑定 SS 对应单元并配对 FF，实例化六路和 PAD。导入网表来自原三位缓存快照；工作区另外提供二位缓存优化，二者的结果分别记录。

### 4.2 六路和真实 PAD 的 RTL 验证

`pad-connect-20261109-v3` 对 87 个输入位、24 个输出位通过原厂带电源 PAD 模型做连接自检，111 位均通过。

`pad-six-20261109-v2` 将六颗 PRN 6～11 的两位合成 IF 经过真实 PAD，实际执行六路独立捕获、跟踪和 NH 解调。每路核对 32 位，合计 192 位通过。场景为无噪声、零多普勒；这是原三位缓存快照的 PAD RTL 验证，不是 SDF 后仿，也不是教师原始数据验收。

### 4.3 无损缓存优化

四电平 −3、−1、+1、+3 的三位补码最低位恒为 1，因此回放缓存可保存高两位，在读取时恢复最低位。通用捕获模块默认仍保存三位；六通道入口启用 `IF2_ONLY` 特化。

六路回放存储从 594432 bit 减至 396288 bit，减少 33.3%；采样率、相关路数和积分窗口保持不变。`tb_handover`、`tb_six_channel_control`、`tb_six_signal` 三项回归全部通过。尚无该优化版本的有效映射面积，不能把存储位数下降当作总单元面积下降。

### 4.4 小规模带电源门级探针

`pad-repair-20261109-v2` 使用真实库反相器对做延迟 ECO，修复小探针保持违例。PrimeTime 按 SS、FF 分别输出 SDF 3.0，VCS 使用原厂带电源模型及 `-negdelay +neg_tchk +define+NTC+RECREM` 保留负时序检查和复位检查的正确匹配。

`pad-gls-20261109-v5` 在两个条件下均功能 PASS，独立 SDF 日志均为 0 errors / 0 warnings。该结果于 15:20 之后取得，只证明工具链和小探针；不表示六路后仿通过。早期只有功能 PASS、仍带反标告警的作业均未作为验收结果。

## 5. 失败、瓶颈和处理

| 问题 | 证据及处理 |
| --- | --- |
| 多核 Ultra 内存不足 | 二位缓存试跑的 3400/4600/6500 MiB 进程虚拟内存上限均触发分配失败；没有有效优化映射，也未将其说成已确认整机内核 OOM。 |
| 单路自动保持修复慢 | 保持违例规模大，增量综合进展慢；原始基线完整保留，完整首次候选先保留违例用于检查。 |
| 导入核心 PG 未连接 | 首次完整集成出现 UPF-581；已显式建立供电对象和连接，失败作业未当作有效网表。 |
| UPF 对象命名冲突 | 逻辑占位电源端口与 supply 对象冲突，改为先移除占位对象再建立 UPF supply 连接。 |
| 电源连接脚本缓慢 | 逐叶单元属性查询、频繁供电更新造成明显开销；后续快照改为批量读取名称和连接，并记录阶段时间。 |
| 旧版 SDF 反标不完整 | 改用 PrimeTime 分角输出 SDF 3.0，并启用原厂 NTC/RECREM 模式，最终在小探针取得零反标错误和告警。 |
