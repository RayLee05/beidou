### 接口和约束决策

1. 六路共用上升沿采样的 16.368 MHz 时钟，每拍均有新 IF，不增加 `if_valid`。编码采用现有四电平约定：`00=-3, 01=-1, 10=+1, 11=+3`。
2. 配置口为 `cfg_valid / cfg_channel[2:0] / cfg_enable / cfg_prn[5:0] / cfg_dop_min[31:0] / cfg_dop_step[31:0] / cfg_bins[7:0]`。选中路在上升沿原子锁存配置，撤销状态、重装 PRN 并重捕获；编号 6、7 无效，不能改变其他路。频率字按 `Hz × 2^32/Fs` 定义。
3. `nav_data` 为已去 NH 的逐位 D1 数据，保留 Costas 整体极性模糊；本阶段不输出整帧/BCH 解码结果。六星用例每路确定一次极性，之后逐位比较，不逐位任意翻转。
4. 捕获移交采用每拍最多推进两个样本相位，消除对共享输入暂停的依赖；装载跟踪时补偿本拍样本，载波和码相位使用相同样本起点。
5. 低有效复位统一作用于六路；释放在下降沿附近并满足所选库 recovery/removal。配置为同步接口。约束不添加宽泛 reset/config false path。
6. 核心预估使用 `constraints/core_exploration.sdc` 的显式临时预算：输入相对时钟 0.5～5 ns、输出 setup 5 ns/hold 0.5 ns、10 fF 核心端负载、0.2 ns 输入转换和 0.5 ns 时钟不确定度。它是核心引脚级建模假设，尚未按真实 PAD 验证，不得直接复制为最终 SDC。M4 必须核对单位、PAD 驱动/电容及板级接口后冻结。

### 资源和故障处理

- 单通道默认 64 路码相位相关，回放缓存 33024×3 bit、非相干次数 2。六路仅回放数据就有 594432 bit，另有 PRN RAM 和控制/环路状态；是否映射到触发器，必须看 DC 推断与单路实测。
- 单路先运行基本 `compile`，保留 `/usr/bin/time -v`。若主机内存不足，先选择真实可用的 RAM 宏或分层映射方案；不能把缩小 TB 参数的结果当正式默认设计。
- 每次修改重新打包、使用新 job 名；长综合后台运行，断线只查询/取回。SSH 认证偶发失败已复现，重试保持严格主机指纹检查；不会通过更改共享 SSH 服务配置或重复启动任务来解决。
- 提交成功仅说明后台启动。日志无 `Error/FATAL`、设计实际映射且 `unmapped=0` 才能认定映射阶段完成；之后仍分别审核黑盒、时序、设计规则与约束覆盖。

## 已确认需要改造的地方

- 现有 `b1i_rx_top` 是十二通道、共享一个捕获引擎。仅将通道数改为六，不满足“每路独立捕获”的要求。新增六通道工程，不直接覆盖原顶层。
- 捕获到跟踪的移交需适配持续输入：共享采样编号连续，各路独立计算自己的移交初值，不能因一路初始化暂停其余五路。
- `capture_ok` 表示当前捕获状态，失锁或重捕获时撤销；`bit_sync_ok` 随同步状态撤销；`nav_valid` 单拍，`nav_data` 在有效时稳定，并明确是否去 NH 及是否校正整体极性。
- 旧 `dc_synth.tcl` 默认单通道、`compile_ultra`，SDC 使用 10 ns 占位，并存在宽泛复位／配置 false path。需为本次实验另写脚本和完整约束。
- 复位先确定合法释放方式，检查适用的恢复、移除和脉宽；普通使能不当作时钟。门级仿真保留 specify、timing check 和 notifier，不能通过关闭检查取得 PASS。
- 拟采用与输入一致的 16.368 MHz 时钟（周期约 61.094819 ns）；若课程另有时钟指标，在首次正式综合前调整并冻结，优化过程中不降频过关。IO 延迟、负载及转换限制根据真实接口和 PAD 库确定，当前不填猜测值。
- 捕获回放缓存、码 RAM 若展开成寄存器，面积和内存开销可能较大。先测单通道，再决定是否使用实际可用的 SRAM 宏；不得缩短必要积分窗口来压低面积。
