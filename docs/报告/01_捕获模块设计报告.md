# 捕获模块设计报告

采样率 16.368 MHz，中频 4.092 MHz，样本 2 bit（`00→-3`，`01→-1`，`10→+1`，`11→+3`）。这三项与教师公开输入约定一致。下面的仿真用的是仓库自己的向量，不是教师 `scenario.if2` 的 100 秒六星文件。

模块在 `rtl/acq/acquisition.sv`。用例 `tb/system/tb_acquisition.sv` 把捕获结果交给跟踪通道，再用一个场景里没有的 PRN 做拒识。

## 1. 设计思路

捕获要在不知道码相位和多普勒的情况下，从实时样本流里找出一颗星，并把码相位交到当前时刻，让跟踪环能接上。

搜索不能对着无限长的实时流做。模块先截一段样本放进回放缓冲，在缓冲上扫多普勒和半码片。截取开始后另记实时样本数 Δ。搜完后用 Δ 把码相位外推到“现在”，再用追赶 NCO 对齐实时流。`ready=1` 时的 `ho_phase` 是最后一个已处理样本处的码相位，可以直接装入 `tracking_channel`。

## 2. 方案

实例参数：`N_LANES=64`，`BUF_DEPTH=33024`。缓冲深度要盖住延迟线预热和相干积分：不少于 `4*(N_LANES-1) + nc*16368`。

状态依次是截取、分轮回放、扫描、判决、细搜、外推、追赶、就绪。

1. **截取。** `CAPTURE` 把实时样本按 2 bit 写入回放 RAM，同时累加 Δ。1 ms 有 16368 个样本。
2. **粗搜。** 多普勒格数由 `n_bins` 给出。每一格分 `4096/64=64` 轮回放。每一轮 64 路并行，第 j 路本地码比第 0 路晚 j 个半码片（延迟线抽头间隔 4 个样本，因为 1 码片 8 个样本）。半码片假设 `h = h0 - j`。先丢掉 `WARM=4*(64-1)` 个样本，把延迟线填满，再做 `nc` 次 1 ms 相干积分。非相干幅度用 `|I|+|Q|/2`。
3. **判决。** 峰值所在多普勒格上，`mean` 是该格相关值之和除以 4096。捕获条件是 `peak*16 > mean*thr`，`thr` 为 Q4.4。本用例 `thr_q4_4=56`，即峰均比门限 `56/16=3.5`。
4. **细搜。** 在最佳假设附近再做 5 个多普勒格，步长为粗步长的 1/4，更新 `(h, 多普勒)`。
5. **移交。** `φ = h·2^36 + (Δ mod 16368)·2^34 + Δ·aid`，再对码周期取模。追赶 NCO 跟上实时流后给出 `ho_phase` 和 `res_dop`。

窗口里第 k 个样本处理完时，第 j 路假设上的信号码相位为 `h·2^36 + (k+1)·inc`，`inc = 2^34 + aid`。`h` 是半码片序号，不是 t=0 的码片真值。

## 3. 仿真

### 3.1 RTL 端到端

向量 `tb/vectors/acq_meta.json`：

| 项 | 值 |
|---|---|
| 目标 PRN / 缺席 PRN | 10 / 6 |
| C/N0 | 45 dB-Hz |
| 多普勒搜索 | 从 −500 Hz 起，步长 500 Hz，5 格 |
| 非相干次数 `nc` | 2 |
| 门限 | Q4.4 的 56（峰均比 3.5） |
| 场景长度 | 650 ms，2 659 800 字节 |
| t=0 码相位真值 | 1554.59 chip |
| t=0 多普勒真值 | 289.03 Hz |

ModelSim SE-64 2020.4，2026-10-04，墙钟 153.66 s，仿真时间 516.8 ms。日志在 `reports/local/acq_summary.txt`。

| 项 | 结果 |
|---|---|
| 捕获完成 | 第 1 791 804 个样本，`found=1` |
| 半码片假设 `h` | 3192 |
| 多普勒频率字 `dop` | 65600（32 bit NCO，约 +250 Hz） |
| `peak` / `mean` | 1 013 221 / 210 098（峰均比约 4.82） |
| 移交 | 约 109 ms |
| 再跟踪 300 ms | `locked=1`，码误差 0.0058 chip |
| 缺席 PRN 6 | `found=0`，`peak/mean=656283/207882`（峰均比约 3.16） |

同一用例 2026-10-09 在虚拟机 IC 上用 VCS I-2014.03 重跑，`reports/sim/tb_acquisition.log` 为 `[PASS]`。

### 3.2 教师场景上的 Python 粗捕

`scripts/probe_teacher_if2.py` 只读了 `scenario.if2` 开头 20 ms，在 ±10 kHz、500 Hz 格上做非相干搜索。这不是 RTL，也没有跟踪闭环。相对中位峰值，比值大于 2 的是：

| PRN | 比值 | 多普勒 | 码相位 |
|---:|---:|---:|---:|
| 11 | 2.99 | −3000 Hz | 1793.00 chip |
| 13 | 2.89 | +500 Hz | 1850.63 chip |
| 8 | 2.84 | +500 Hz | 470.63 chip |
| 28 | 2.49 | +1000 Hz | 1219.63 chip |
| 21 | 2.39 | −2000 Hz | 1283.50 chip |

公开场景写明 6 颗星。这次 20 ms 粗捕只分出上面 5 颗，第 6 颗没有拉开。

## 4. 结果分析

目标星峰均比 4.82，高于门限 3.5，判为捕获。缺席 PRN 6 的峰均比 3.16，低于门限，`found=0`，没有误捕。

频率字 65600 对应约 +250 Hz。向量在 t=0 的多普勒真值是 289 Hz，粗步长 500 Hz，细步长 125 Hz，250 Hz 落在细格上，和真值差约 40 Hz。这个残差交给后面的跟踪环，不在捕获里收成 0。

`h=3192` 不能和 t=0 的 1554.59 chip 直接比。捕获结束时已经过了约 109 ms，码相位被 Δ 外推过。移交是否可用，看的是随后 300 ms 跟踪：锁定，码误差 0.0058 chip。

## 5. 局限

- RTL 证据是 45 dB-Hz、单目标、5 个多普勒格、650 ms。教师场景是 40 dB-Hz、六星、100 秒，RTL 还没在那份 `scenario.if2` 上跑完。
- 20 ms Python 粗捕没有给出第 6 颗星。
- 捕获多普勒仍是格点值。频率字到载波 NCO 的交接由跟踪环继续收。
